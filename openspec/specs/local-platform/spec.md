## Purpose

Кроссплатформенный локальный сервер, API, хранение метаданных и защитные границы для файловых и CLI-операций OpenSpec Studio.
## Requirements
### Requirement: Локальный сервер
Система SHALL работать на macOS, Linux и Windows и по умолчанию слушать только случайный свободный порт loopback-интерфейса.

#### Scenario: Попытка внешнего bind
- **WHEN** конфигурация содержит не-loopback address
- **THEN** сервер отказывается запускаться с понятной диагностикой

### Requirement: Единый локальный API
Система SHALL предоставлять версионированный JSON API под `/api/v1`, единый формат ошибок, correlation ID и SSE для длительных операций, а browser UI SHALL использовать этот API как источник истины для поддержанных системных данных и project metadata.

#### Scenario: Успешный ответ
- **WHEN** browser UI запрашивает системные данные или проекты
- **THEN** UI использует типизированный JSON-ответ локального API без обращения к файловой системе и без подстановки демонстрационных данных

#### Scenario: Ошибка запроса
- **WHEN** endpoint отклоняет операцию
- **THEN** ответ содержит `error.code`, безопасное сообщение, details и correlationId, а UI сохраняет эти диагностические поля для отображения

### Requirement: Защита web API
Система SHALL отклонять изменяющие запросы без локального CSRF token и запросы от неразрешённого origin, включая запись Markdown-файлов.

#### Scenario: Запись из browser UI
- **WHEN** UI отправляет явную запись Markdown-файла
- **THEN** запрос содержит актуальный session CSRF token и backend проверяет его до файловой операции

#### Scenario: Чужой origin
- **WHEN** browser-запрос приходит от произвольного внешнего origin
- **THEN** сервер отклоняет его до выполнения бизнес-логики

#### Scenario: Изменяющий запрос из UI
- **WHEN** пользователь создаёт, переименовывает или удаляет проект
- **THEN** browser UI передаёт актуальный session CSRF token в запросе к локальному API

#### Scenario: Устаревшая session
- **WHEN** backend отклоняет изменяющий запрос с `CSRF_REJECTED`
- **THEN** UI обновляет session token и допускает не более одного автоматического повтора исходной операции

### Requirement: Безопасность путей
Система SHALL нормализовать каждый относительный путь файлового API, разрешать его относительно Store активного проекта и проверять существующий файл и его symlink-компоненты до чтения или записи.

#### Scenario: Traversal
- **WHEN** API получает `../`, абсолютный путь или путь вне разрешённых OpenSpec-каталогов
- **THEN** сервер возвращает `PATH_OUTSIDE_SCOPE` и не обращается к целевому файлу

#### Scenario: Symlink escape
- **WHEN** допустимый по форме путь через symlink разрешается за пределами Store
- **THEN** сервер возвращает `PATH_OUTSIDE_SCOPE` и не читает и не изменяет внешний файл

### Requirement: Управление CLI-процессами
Система SHALL запускать CLI без shell-интерполяции и скрытых пользовательских
аргументов, с контролируемыми executable, `cwd`, stdin и окружением,
настраиваемым timeout, cancellation, завершением дерева процессов и
ограниченным безопасным захватом stdout/stderr.

#### Scenario: Timeout
- **WHEN** процесс превышает установленный лимит
- **THEN** сервер завершает дерево процесса и возвращает соответствующий код ошибки без применения частичного результата

#### Scenario: Отмена
- **WHEN** пользователь отменяет длительную CLI-операцию
- **THEN** сервер завершает дочерний процесс и созданные им процессы, дожидается контролируемого завершения и сохраняет статус cancelled

#### Scenario: Аргумент начинается с дефиса
- **WHEN** пользовательское значение может быть интерпретировано CLI как option
- **THEN** adapter передаёт его только в позиции данных или через stdin и не допускает изменения списка разрешённых аргументов

#### Scenario: Небезопасное окружение
- **WHEN** родительский процесс содержит переменную окружения вне разрешённого набора
- **THEN** дочерний CLI не наследует её, кроме явно предусмотренных adapter policy значений

#### Scenario: Git использует системный SSH agent
- **WHEN** Git adapter запускает clone SSH URL и приложение имеет непустой `SSH_AUTH_SOCK`
- **THEN** дочерний процесс получает только это явно разрешённое SSH-значение без наследования иных SSH-настроек

### Requirement: Локальная SQLite
Система SHALL хранить проекты, настройки, черновики, AI-историю и журнал операций в версионированной SQLite-схеме без копирования содержимого репозиториев.

#### Scenario: Перезапуск
- **WHEN** приложение запускается повторно
- **THEN** сохранённые проекты, настройки и черновики восстанавливаются после миграций

### Requirement: Изоляция проектов
Система SHALL обрабатывать ошибку одного проекта без остановки локального сервера и других проектов.

#### Scenario: Сбой adapter
- **WHEN** операция одного проекта завершается panic или ошибкой CLI
- **THEN** сервер возвращает контролируемую ошибку, оставаясь готовым для последующих запросов

### Requirement: Журнал длительной CLI-операции
Система SHALL сохранять correlation ID, тип операции, безопасное имя executable,
редактированные аргументы, время запуска и завершения, exit code, причину
остановки и ограниченную диагностику без prompt, секретов и полного файлового
контекста.

#### Scenario: Успешное завершение
- **WHEN** CLI-процесс завершается
- **THEN** диагностический журнал доступен из истории операции и не содержит credentials или полного prompt

#### Scenario: Редактирование чувствительного аргумента
- **WHEN** adapter помечает аргумент или переменную как чувствительные
- **THEN** журнал сохраняет вместо значения стабильную отметку `[REDACTED]`

### Requirement: Восстановление прерванных операций
Система SHALL при старте переводить сохранённые queued, running или validating
операции, не имеющие управляемого живого процесса, в failed с причиной
`APPLICATION_RESTARTED`.

#### Scenario: Перезапуск приложения во время операции
- **WHEN** OpenSpec Studio запускается после незавершённой clone или AI-операции
- **THEN** операция больше не считается активной, сохраняет историю событий и может быть повторена явным действием пользователя
