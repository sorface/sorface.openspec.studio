## Purpose

Безопасное визуальное редактирование OpenSpec Markdown с локальными ревизиями черновиков и защитой от потери внешних изменений.

## Requirements

### Requirement: Дерево OpenSpec
Система SHALL показывать Markdown-артефакты в `openspec/specs/`, активных `openspec/changes/` и архиве активного Store worktree.

#### Scenario: Пустой Store
- **WHEN** допустимые каталоги не содержат артефактов
- **THEN** UI показывает пустое состояние и доступное действие создания

### Requirement: Визуальный Markdown-редактор
Система SHALL позволять аналитику редактировать Markdown без знания синтаксиса через визуальное форматирование заголовков, списков, ссылок, таблиц, цитат и блоков кода.

#### Scenario: Визуальное форматирование
- **WHEN** пользователь применяет форматирование через toolbar или slash-команду
- **THEN** редактор обновляет документ и сохраняет результат как переносимый Markdown, а не HTML

### Requirement: Режимы представления
Система SHALL поддерживать режимы `Edit`, `Preview` и `Split`, включая безопасный рендеринг Mermaid.

#### Scenario: Split
- **WHEN** пользователь выбирает `Split`
- **THEN** UI одновременно показывает редактируемое содержимое и актуальный preview

### Requirement: Отдельный черновик
Система SHALL хранить изменения в локальном черновике отдельно от файла working tree и создавать новую ревизию без потери предыдущей.

#### Scenario: Автосохранение
- **WHEN** пользователь прекращает ввод
- **THEN** новая ревизия черновика сохраняется не позднее чем через 2 секунды, а Git-файл не изменяется

### Requirement: Явная запись на диск
Система SHALL записывать черновик в Store только по явной команде пользователя и выполнять запись атомарно.

#### Scenario: Успешная запись
- **WHEN** базовый файл не изменился после создания черновика
- **THEN** файл атомарно обновляется и Git diff отражает новое содержимое

### Requirement: Конфликт внешнего изменения
Система MUST NOT тихо перезаписывать файл, хеш которого отличается от `baseContentHash` черновика.

#### Scenario: Файл изменён внешним редактором
- **WHEN** пользователь пытается записать устаревший черновик
- **THEN** запись блокируется с `DRAFT_CONFLICT`, а UI предлагает сравнение и разрешение конфликта

### Requirement: Файловые операции
Система SHALL позволять создавать, переименовывать и удалять только допустимые OpenSpec-файлы и каталоги внутри активного Store.

#### Scenario: Путь вне Store
- **WHEN** запрос содержит traversal или разрешается за пределами Store через symlink
- **THEN** система отклоняет его с `PATH_OUTSIDE_SCOPE`
