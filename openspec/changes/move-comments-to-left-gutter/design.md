## Context

См. `proposal.md` — Why. Подсветка уже реализована ProseMirror decorations, а карточки комментариев и кнопка добавления позиционируются независимо: карточки абсолютно внутри `rich-editor-shell`, кнопка — фиксированно через координаты выделения во viewport.

## Goals / Non-Goals

**Goals:**

- Вычислять кнопку добавления относительно левого края выделенного текстового блока.
- Размещать открытые карточки в зарезервированном левом gutter редактора.
- Сохранить текущие comment ids, decorations, переход к фрагменту и удаление.

**Non-Goals:**

- Менять модель комментария, persistence или OpenSpec action goal.
- Привязывать каждую карточку по вертикали к точной строке фрагмента.

## Decisions

### Левый gutter резервируется только при наличии комментариев

`rich-editor-shell` получает state-class при непустом списке комментариев. На desktop класс увеличивает левое внутреннее пространство Milkdown, а панель располагается слева внутри shell. Так карточки участвуют в одной прокрутке с документом и не перекрывают текст. Постоянно уменьшать ширину редактора при отсутствии комментариев не требуется.

Альтернатива — fixed overlay у края viewport — отвергнута: overlay теряет связь с editor shell и может перекрыть навигацию.

### Кнопка использует левую координату выделения

Floating action остаётся portal-элементом, но его `left` вычисляется перед левым краем selection с ограничением по viewport. Это сохраняет корректность при прокрутке и не требует доступа к внутреннему layout Milkdown.

Альтернатива — ProseMirror widget decoration — существенно усложняет управление native selection и формой создания комментария.

### Подсветка остаётся decoration

Существующий `editor-comment-highlight` сохраняется как inline decoration; меняются только контрастные жёлтые токены. Это не добавляет разметку в Markdown и автоматически удаляет подсветку вместе с comment id.

## Risks / Trade-offs

- [Панель уменьшает доступную ширину документа] → резервировать gutter только при комментариях и отключать резервирование на узком viewport.
- [Кнопка выходит за левый край окна] → ограничить координату безопасным viewport inset.
- [Несколько комментариев образуют длинный список] → оставить независимую прокрутку панели с ограниченной высотой.

## Migration Plan

Миграция данных не требуется. Изменение развёртывается вместе с frontend bundle; rollback возвращает прежние JSX/CSS без преобразования сохранённых комментариев.
