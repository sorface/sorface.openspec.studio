## Why

OpenSpec Studio уже обнаруживает Git, Codex и GigaCode CLI и управляет
метаданными проектов, но не может клонировать кодовые репозитории или выполнять
AI-операции. Без этих двух сценариев workspace остаётся демонстрационным:
пользователь не может подключить фактический кодовый контекст и получить
проверяемое предложение изменения Store.

## Цель

Довести основной локальный сценарий до работающей вертикали: безопасно
клонировать связанный с проектом кодовый Git-репозиторий, выбрать разрешённый
контекст и запустить установленный agent CLI так, чтобы его результат проходил
аудит области записи и попадал на review до применения.

## Scope

- Добавить clone и подключение кодового репозитория по Git URL через локальный
  backend с явным целевым каталогом, прогрессом, отменой и очисткой только
  созданного незавершённого clone-каталога.
- Проверять Git-структуру, `store` в `openspec/config.yaml`, совпадение Store ID
  и read-only статус репозитория до сохранения подключения.
- Хранить подключённые репозитории и выбранную ветку в SQLite, показывать их
  состояние в workspace и не копировать содержимое репозиториев в базу.
- Добавить единый безопасный process runner без shell-интерполяции для Git,
  Codex и GigaCode с контролируемыми `cwd`, окружением, timeout, cancellation и
  ограниченным захватом вывода.
- Добавить API создания, чтения, наблюдения через SSE и отмены AI-операций.
- Формировать подтверждаемый пользователем текстовый контекст, исключая
  секретные, бинарные, запрещённые и превышающие лимит файлы.
- Создавать изолированный operation workspace из снимка активного Store,
  запускать agent CLI только в нём, предоставлять кодовые репозитории как
  отфильтрованный текстовый контекст и выполнять post-operation audit.
- Сохранять результат операции и безопасный журнал, показывать предложенный
  diff и переводить успешную операцию в `awaiting_review` без автоматической
  записи результата в working tree.
- Покрыть backend, frontend и интеграционные сценарии автоматическими тестами.

## Вне scope

- Клонирование или первичное создание самого OpenSpec Store.
- Управление Git credentials, SSH-ключами, токенами и credential helpers.
- Автоматический stash, discard, commit или push кодовых репозиториев.
- Создание и удаление Git worktree.
- Частичное принятие результата по hunks и запись принятого черновика на диск;
  этот change доводит AI-операцию до review-ready результата.
- Интерактивный terminal/PTY и произвольный запуск пользовательских команд.
- Фоновое выполнение после завершения локального процесса OpenSpec Studio.

## What Changes

- Появятся REST/SSE endpoints репозиториев и длительных операций.
- SQLite-схема получит таблицы подключённых репозиториев, операций, событий и
  безопасного аудита.
- Backend получит изолированные Git и AI adapters поверх общего process runner.
- Workspace заменит статические данные репозиториев, контекста и AI-панели
  подтверждённым серверным состоянием.
- Неуспешный clone или AI-запуск будет завершаться контролируемой ошибкой без
  скрытого изменения Store или подключённых кодовых репозиториев.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `repository-context`: конкретизировать наблюдаемое поведение clone, прогресс,
  отмену, проверку назначения каталога и атомарную регистрацию репозитория.
- `ai-operations`: конкретизировать создание и запуск операции, контекстный
  manifest, события SSE, ограничения вывода, отмену и проверку области записи.
- `local-platform`: определить общий контракт длительных CLI-процессов,
  завершение дерева процессов и восстановление состояния после перезапуска.

## Impact

- Backend: новые application services, Git/agent adapters, process supervisor,
  path policy, HTTP handlers и SQLite migration.
- Frontend: feature-модули repositories и AI operations, server-backed панели,
  состояния progress/error/cancel/review.
- API: новые маршруты под `/api/v1/projects/{projectId}` для repositories и AI
  operations; существующие endpoints остаются совместимыми.
- Системные зависимости: используются уже обнаруживаемые `git`, `codex` и
  `gigacode`; новые runtime-секреты и shell-зависимости не добавляются.

## Риски

- Различия аргументов и форматов вывода Codex/GigaCode могут привести к утечке
  provider-specific логики — adapters обязаны переводить их в единый контракт.
- Завершение дерева процессов отличается между ОС — поведение проверяется
  платформенными unit/integration тестами и имеет ограниченный timeout.
- Симлинки и внешние Git metadata могут обходить проверку пути — trusted roots
  проверяются до запуска и повторно после разрешения symlink.
- Agent CLI способен изменить неожиданные файлы — pre/post snapshot и аудит
  изолированного operation workspace отклоняют весь результат при выходе за
  разрешённую структуру Store, а реальный working tree не передаётся на запись.
- Большой stdout или репозиторий может исчерпать память — вывод, размер файлов,
  число файлов и общий контекст ограничиваются конфигурацией.
