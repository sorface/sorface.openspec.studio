## ADDED Requirements

### Requirement: Клонирование кодового репозитория
Система SHALL клонировать кодовый Git-репозиторий по URL только в выбранный
пользователем отсутствующий или пустой каталог после проверки допустимости URL и
целевого пути.

#### Scenario: Успешное клонирование
- **WHEN** пользователь подтверждает корректный Git URL и доступный пустой каталог
- **THEN** система клонирует репозиторий, проверяет его связь со Store проекта и регистрирует подключение только после успешной проверки

#### Scenario: Непустой целевой каталог
- **WHEN** выбранный целевой каталог содержит файлы до начала операции
- **THEN** система возвращает `CLONE_TARGET_NOT_EMPTY` и не изменяет содержимое каталога

#### Scenario: Недопустимая схема URL
- **WHEN** Git URL использует неподдерживаемую схему или интерпретируется как аргумент CLI
- **THEN** система возвращает `INVALID_GIT_URL` до запуска Git

### Requirement: Наблюдаемая clone-операция
Система SHALL выполнять clone как длительную операцию со статусами queued,
running, validating, completed, cancelled и failed, безопасным прогрессом и
возможностью отмены.

#### Scenario: Прогресс клонирования
- **WHEN** clone находится в состоянии running или validating
- **THEN** UI показывает текущий статус и получает новые события без блокировки остальных проектов

#### Scenario: Отмена клонирования
- **WHEN** пользователь отменяет running clone
- **THEN** система завершает дерево Git-процесса, переводит операцию в cancelled и удаляет только каталог, созданный этой незавершённой операцией

### Requirement: Атомарная регистрация репозитория
Система MUST сохранять подключённый репозиторий в проекте только после успешной
проверки Git-структуры, канонического пути, Store ID, текущей ветки и commit SHA.

#### Scenario: Store ID не совпадает после clone
- **WHEN** клонированный репозиторий содержит `store`, отличный от Store ID проекта
- **THEN** система возвращает `STORE_ID_MISMATCH`, не регистрирует репозиторий и предлагает пользователю удалить созданный clone-каталог

#### Scenario: Ошибка сохранения метаданных
- **WHEN** проверка репозитория успешна, но сохранение подключения завершается ошибкой
- **THEN** репозиторий не появляется в проекте, а существующее содержимое clone-каталога не удаляется автоматически

### Requirement: Серверное состояние подключённых репозиториев
Система SHALL возвращать для каждого подключённого репозитория подтверждённые
сервером имя, канонический путь, remote URL, ветку или detached HEAD, commit SHA,
чистоту working tree и `readOnlyForAi: true`.

#### Scenario: Повторное открытие проекта
- **WHEN** пользователь открывает проект после перезапуска приложения
- **THEN** UI загружает сохранённые репозитории и заново проверяет их доступность и текущее Git-состояние

#### Scenario: Каталог стал недоступен
- **WHEN** сохранённый путь больше не существует или перестал быть тем же Git-репозиторием
- **THEN** UI помечает подключение как unavailable без автоматического удаления метаданных
