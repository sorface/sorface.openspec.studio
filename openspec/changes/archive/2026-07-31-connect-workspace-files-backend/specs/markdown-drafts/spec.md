## MODIFIED Requirements

### Requirement: Дерево OpenSpec
Система SHALL получать через backend и показывать Markdown-артефакты в `openspec/specs/`, активных `openspec/changes/` и `openspec/archive` активного Store worktree без демонстрационных файлов.

#### Scenario: Реальный Store
- **WHEN** пользователь открывает проект с доступным Store
- **THEN** UI показывает только найденные backend допустимые каталоги и `.md`-файлы с относительными путями

#### Scenario: Пустой Store
- **WHEN** допустимые каталоги не содержат артефактов
- **THEN** UI показывает пустое состояние без подстановки демонстрационных документов

### Requirement: Явная запись на диск
Система SHALL записывать изменённое Markdown-содержимое в Store только по явной команде пользователя, выполнять запись атомарно и возвращать новый хеш содержимого.

#### Scenario: Успешная запись
- **WHEN** базовый файл не изменился после его загрузки в редактор и пользователь явно подтверждает запись
- **THEN** файл атомарно обновляется, UI принимает возвращённый хеш как новую базовую версию и снимает признак несохранённых изменений

#### Scenario: Ошибка записи
- **WHEN** backend отклоняет или не может завершить запись
- **THEN** UI сохраняет введённое содержимое, показывает безопасную ошибку и не сообщает об успешном сохранении

### Requirement: Конфликт внешнего изменения
Система MUST NOT тихо перезаписывать файл, текущий хеш которого отличается от переданного `baseContentHash`.

#### Scenario: Файл изменён внешним редактором
- **WHEN** пользователь пытается записать содержимое с устаревшим `baseContentHash`
- **THEN** backend возвращает `DRAFT_CONFLICT`, не изменяет файл, а UI сохраняет ввод и предлагает повторно загрузить документ

### Requirement: Файловые операции
Система SHALL разрешать чтение и запись только существующих допустимых UTF-8 Markdown-файлов внутри `openspec/specs`, `openspec/changes` и `openspec/archive` активного Store.

#### Scenario: Путь вне Store
- **WHEN** запрос содержит абсолютный путь, traversal или разрешается за пределами Store через symlink
- **THEN** система отклоняет его с `PATH_OUTSIDE_SCOPE`

#### Scenario: Недопустимый файл
- **WHEN** запрошен файл вне разрешённых OpenSpec-каталогов, файл без расширения `.md`, невалидный UTF-8 или файл сверх допустимого размера
- **THEN** система отклоняет запрос с безопасным кодом ошибки и не читает содержимое в UI
