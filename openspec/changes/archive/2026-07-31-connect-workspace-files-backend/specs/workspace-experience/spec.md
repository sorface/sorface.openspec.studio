## MODIFIED Requirements

### Requirement: Основные экраны
Система SHALL предоставлять workspace, в котором дерево документов, выбранный Markdown-файл и действие явной записи используют backend активного проекта как источник истины.

#### Scenario: Открытие проекта
- **WHEN** пользователь выбирает существующий проект
- **THEN** UI загружает дерево его Store, выбирает первый доступный Markdown-файл и показывает полученное от backend содержимое в редакторе

#### Scenario: Выбор документа
- **WHEN** пользователь выбирает другой файл без несохранённых изменений
- **THEN** UI загружает его актуальное содержимое через backend и обновляет редактор

## ADDED Requirements

### Requirement: Понятная группировка документов
Workspace SHALL представлять OpenSpec-документы двухуровневой навигацией: три независимых сворачиваемых раздела «Документация», «Изменения» и «Архив» SHALL содержать только названия спецификаций, активных changes и архивных changes, а дерево Markdown-файлов SHALL открываться в отдельной соседней grid-панели после выбора конкретной сущности. Эта панель SHALL занимать собственную колонку и сдвигать редактор, а не перекрывать его. Workspace MUST NOT показывать технические корневые каталоги Store как отдельные элементы навигации.

#### Scenario: Загрузка смешанного дерева
- **WHEN** backend возвращает документы baseline specs, активных changes и архива
- **THEN** UI помещает в разделы «Документация», «Изменения» и «Архив» только названия соответствующих сущностей без вложенных каталогов и Markdown-файлов

#### Scenario: Выбор сущности
- **WHEN** пользователь выбирает название спецификации, активного change или архивного change
- **THEN** UI открывает справа от основной навигации отдельную панель с деревом только этой сущности и позволяет выбрать в ней Markdown-файл

#### Scenario: Панель дерева не перекрывает редактор
- **WHEN** открыта панель Markdown-дерева выбранной сущности
- **THEN** workspace выделяет ей самостоятельную колонку между основной навигацией и редактором, а редактор остаётся видимым справа без наложения панели

#### Scenario: Выбор Markdown-файла
- **WHEN** пользователь выбирает Markdown-файл в панели конкретной сущности
- **THEN** UI загружает документ в редактор по его реальному относительному пути, не изменяя файловую структуру Store

#### Scenario: Архив не вложен в активные изменения
- **WHEN** архивные документы находятся внутри `openspec/changes/archive` или совместимого каталога `openspec/archive`
- **THEN** UI показывает их только в самостоятельном разделе «Архив», а не внутри раздела «Изменения»

#### Scenario: Независимое сворачивание раздела
- **WHEN** пользователь сворачивает один из трёх разделов
- **THEN** UI скрывает только список названий этого раздела, сохраняет состояния остальных разделов и не изменяет выбранную сущность или документ

## MODIFIED Requirements

### Requirement: Обязательные состояния
Workspace SHALL иметь различимые состояния loading, empty, success, error, backend unavailable, dirty, saving и draft conflict и MUST NOT представлять локальное изменение как успешную серверную запись.

#### Scenario: Загрузка дерева
- **WHEN** UI ожидает список документов активного проекта
- **THEN** sidebar показывает состояние загрузки и не отображает статические документы

#### Scenario: Несохранённый документ
- **WHEN** редактор содержит изменения относительно загруженной базовой версии
- **THEN** UI показывает dirty-состояние и не заменяет содержимое автоматически при выборе проекта или файла

#### Scenario: Backend недоступен
- **WHEN** чтение или запись завершается сетевой ошибкой
- **THEN** UI сохраняет текущий ввод, показывает backend unavailable и доступное действие повтора
