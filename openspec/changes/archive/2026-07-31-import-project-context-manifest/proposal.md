## Why

Сейчас при клонировании OpenSpec Store пользователь вручную задаёт название проекта и отдельно подключает каждый кодовый репозиторий. Переносимый `.openspec/context.yaml` позволит восстановить проект и его read-only контекст одной операцией из Git.

## Цель

Сделать OpenSpec-репозиторий самодостаточным описанием проекта: после клонирования Studio автоматически применяет имя из манифеста и подключает перечисленные Git-репозитории в контекст.

## What Changes

- Добавляется поддержка корневого файла `.openspec/context.yaml` с обязательным `name` и списком `context.repositories` из Git URL.
- При клонировании Store имя из корректного манифеста имеет приоритет над ручным fallback-именем.
- Все URL манифеста проверяются и дедуплицируются до запуска контекстных clone-операций.
- Контекстные репозитории клонируются в управляемую область проекта, регистрируются как `readOnlyForAi: true` и становятся доступны на странице «Контекст».
- Результат создания проекта содержит сводку импорта, включая безопасные ошибки отдельных репозиториев и возможность повторить их вручную.
- При отсутствии манифеста сохраняется существующий сценарий создания проекта с ручным названием.

## Scope

- Чтение и строгая валидация только `.openspec/context.yaml` внутри уже клонированного Store.
- Автоматический импорт HTTPS, SSH URL и SCP-подобных SSH URL, которые уже разрешены Studio.
- Backend, project API, форма создания проекта и автоматические тесты полного сценария.

## Вне scope

- Хранение credentials, токенов, веток или локальных путей в манифесте.
- Автоматический commit или изменение `context.yaml` из UI.
- Удаление уже успешно клонированного Store при ошибке одного контекстного репозитория.
- Параллельное клонирование и отдельный batch-operation API.

## Capabilities

### New Capabilities

- `project-context-manifest`: формат, валидация и применение переносимого `.openspec/context.yaml`.

### Modified Capabilities

- `project-store-management`: клонирование Store получает имя проекта из манифеста и возвращает результат импорта.
- `repository-context`: перечисленные в манифесте репозитории автоматически клонируются и регистрируются как read-only контекст.

## Impact

- Backend: `project`, `repository`, `storegit`, HTTP API и wiring приложения.
- Frontend: типы project API, controller и форма клонирования.
- Новая Go-зависимость для безопасного YAML-декодирования.
- API `POST /api/v1/projects/from-git` принимает опциональное fallback-имя и возвращает аддитивную сводку `contextImport`.

## Риски

- Ошибка или недоступность одного remote может задержать создание проекта; импорт выполняется последовательно с существующими timeout и безопасной Git-аутентификацией.
- Некорректный манифест может сделать репозиторий непереносимым; Studio возвращает стабильную ошибку с путём поля без вывода чувствительных данных.
- Частичный импорт возможен после успешного создания проекта; UI явно показывает результат, а не сообщает ложный полный успех.
