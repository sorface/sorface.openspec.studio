## ADDED Requirements

### Requirement: Исследование перед созданием change
Система SHALL начинать создание change с read-only explore по описанию задачи аналитика и MUST NOT создавать или изменять файлы Store до явного подтверждения создания change.

#### Scenario: Успешное исследование
- **WHEN** аналитик вводит суть задачи и запускает исследование
- **THEN** agent анализирует доступный контекст, возвращает вывод исследования и предлагает перейти к созданию change без изменения Store

#### Scenario: Ошибка исследования
- **WHEN** agent CLI недоступен или explore завершается ошибкой
- **THEN** система сохраняет введённое описание, показывает безопасную ошибку и позволяет повторить исследование

### Requirement: Наблюдаемая валидация change
Система SHALL запускать OpenSpec validate для выбранного change и показывать отдельное состояние проверки вместе с диагностикой, полученной от фактического OpenSpec CLI.

#### Scenario: Change валиден
- **WHEN** OpenSpec validate завершается без диагностических ошибок
- **THEN** аналитик видит заметный статус «Спецификация валидна» для выбранного change

#### Scenario: Change невалиден
- **WHEN** OpenSpec validate возвращает ошибки
- **THEN** аналитик видит статус «Требует исправления», список диагностик и доступное действие обновления спецификации через agent

## MODIFIED Requirements

### Requirement: Создание change
Система SHALL проверять выбранный аналитиком kebab-case идентификатор и отсутствие существующего change после завершённого explore и до запуска AI-сценария создания.

#### Scenario: Успешное предложение
- **WHEN** аналитик завершил explore, задаёт новый идентификатор и подтверждает создание
- **THEN** AI/OpenSpec формируют reviewable diff нового именованного change, не записывая его автоматически

#### Scenario: Недопустимое название
- **WHEN** аналитик задаёт невалидный или уже существующий идентификатор
- **THEN** система не запускает AI-операцию и объясняет, как исправить название

### Requirement: Продолжение change
Система SHALL получать фактический status change и формировать только следующий доступный артефакт согласно инструкциям OpenSpec, включая последовательную подготовку `proposal.md` и delta specs после создания change и их обновление после ручных правок аналитика.

#### Scenario: Подготовка proposal и specs
- **WHEN** новый change создаётся после explore
- **THEN** agent последовательно готовит `proposal.md`, затем ставшие доступными delta specs согласно фактическим инструкциям и зависимостям OpenSpec и показывает единый diff до записи

#### Scenario: Обновление после правки proposal
- **WHEN** аналитик изменил и явно записал `proposal.md`, затем выбирает обновление спецификации
- **THEN** agent получает актуальный proposal и инструкции OpenSpec, формирует reviewable diff delta specs и не перезаписывает их без принятия

#### Scenario: Заблокированный артефакт
- **WHEN** обязательная зависимость артефакта не готова
- **THEN** UI показывает блокировку и не запускает его генерацию
