## Purpose

Связывает работу аналитика с выбранным им номером Jira-задачи и изолированным Store worktree, не вводя собственные статусы или workflow задач.

## ADDED Requirements

### Requirement: Постоянный контекст задачи
Workspace SHALL постоянно показывать номер текущей задачи и MUST использовать точное имя связанной Git-ветки как её пользовательский идентификатор без вычисления Jira-статуса.

#### Scenario: Открыт task workspace
- **WHEN** проект имеет активный task workspace ветки `BILL-1842`
- **THEN** верхняя панель показывает branch-иконку и «BILL-1842» как текущую задачу во всех документных и OpenSpec-представлениях

#### Scenario: Основная ветка без задачи
- **WHEN** активный Store использует основную ветку и пользователь ещё не выбрал задачу
- **THEN** selector показывает фактическое имя ветки и предлагает перейти к Jira-задаче, не присваивая ей вымышленный статус

### Requirement: Пользовательское имя задачи
Система SHALL позволять пользователю ввести непустое имя задачи/ветки, SHALL проверять его по правилам Git branch name и MUST передавать Git только проверенное значение как отдельный аргумент.

#### Scenario: Новая Jira-задача
- **WHEN** пользователь вводит свободное имя `BILL-1842` и подтверждает открытие
- **THEN** система создаёт одноимённую локальную ветку и изолированный task workspace от актуальной локальной базовой ветки

#### Scenario: Существующая задача
- **WHEN** введённое имя соответствует существующему управляемому task workspace либо локальной ветке
- **THEN** система переиспользует связанный workspace или безопасно создаёт для ветки новый worktree без изменения другого worktree

#### Scenario: Некорректное имя
- **WHEN** значение пустое, option-like, содержит traversal либо не проходит Git check-ref-format
- **THEN** система не создаёт ветку или каталог и показывает краткую ошибку у поля

### Requirement: Переключение между задачами
Система SHALL переключать задачу сменой активного task workspace и MUST NOT требовать commit, stash, discard либо чистый working tree покидаемой задачи.

#### Scenario: В покидаемой задаче есть изменения
- **WHEN** пользователь открывает `BILL-1907`, находясь в изменённом worktree `BILL-1842`
- **THEN** изменения `BILL-1842` остаются в его worktree, а документы и OpenSpec context загружаются из worktree `BILL-1907`

#### Scenario: Переключение завершилось
- **WHEN** backend подтвердил новый активный task workspace
- **THEN** UI обновляет selector, дерево документов, открытый файл и OpenSpec overview как одно согласованное состояние

### Requirement: Неизменяемый контекст операции
Каждая файловая, OpenSpec, agent и publication операция MUST сохранять task workspace и канонический Store path при создании и MUST продолжать использовать их при последующем переключении пользователя.

#### Scenario: Переключение во время agent-операции
- **WHEN** agent-операция была запущена для `BILL-1842`, после чего пользователь открыл `BILL-1907`
- **THEN** результат и аудит операции остаются привязаны к worktree `BILL-1842` и не могут записать данные в `BILL-1907`

#### Scenario: Workspace исчез
- **WHEN** сохранённый task workspace больше не принадлежит Store либо его путь недоступен
- **THEN** операция завершается безопасной ошибкой до записи, а система не подменяет контекст текущим активным workspace
