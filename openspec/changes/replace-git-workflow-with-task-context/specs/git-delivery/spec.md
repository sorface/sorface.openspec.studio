## ADDED Requirements

### Requirement: Подготовка публикации задачи
Система SHALL формировать для текущей задачи reviewable публикацию из точного ограниченного набора изменённых OpenSpec-артефактов и MUST немедленно показывать номер задачи, количество файлов и редактируемое commit message до изменения Git history, не ожидая agent CLI.

#### Scenario: Есть OpenSpec-изменения
- **WHEN** task worktree содержит изменённые OpenSpec-артефакты относительно HEAD
- **THEN** UI сразу показывает компактное подтверждение публикации с задачей, перечнем либо количеством артефактов и детерминированным редактируемым сообщением

#### Scenario: Изменений нет
- **WHEN** разрешённый diff публикации пуст
- **THEN** действие публикации недоступно и интерфейс сообщает «Нет изменений для публикации» без запуска agent или Git mutation

#### Scenario: Есть несвязанные файлы
- **WHEN** worktree содержит изменения вне разрешённой OpenSpec-области публикации
- **THEN** эти файлы не входят в diff, commit или agent context и UI сообщает, что они останутся локальными

### Requirement: Agent-generated commit message
Система SHALL запускать настроенного agent только по явному выбору пользователя, SHALL передавать ему только номер задачи, список путей и ограниченный diff будущего commit и SHALL принимать русский `subject` и `body` без полномочий на файловые или Git mutations.

#### Scenario: Agent сформировал сообщение
- **WHEN** provider возвращает допустимый русский subject и body, основанные на переданном diff
- **THEN** система принимает subject в формате `<branch>: <короткое сообщение>`, body как непустой маркированный список изменений, сохраняет их вместе с fingerprint diff и показывает перед публикацией

#### Scenario: Agent недоступен или ответ некорректен
- **WHEN** provider отсутствует, завершается ошибкой, превышает timeout либо возвращает невалидное сообщение
- **THEN** система сохраняет введённое пользователем сообщение, показывает исправимую ошибку генерации и позволяет продолжить публикацию вручную

#### Scenario: Diff превышает лимит
- **WHEN** полный разрешённый diff превышает предел agent context
- **THEN** система передаёт bounded summary и усечённый diff с явным признаком truncation, не включая запрещённые файлы

### Requirement: Пользовательское commit message
Система SHALL позволять пользователю редактировать subject и body до подтверждения публикации и MUST принимать публикацию без запуска agent, если subject начинается с точного `<branch>:` и содержит непустое короткое описание.

#### Scenario: Ручное сообщение
- **WHEN** пользователь вводит допустимый subject и необязательный body и подтверждает публикацию
- **THEN** backend использует подтверждённый текст без обязательного запуска agent

#### Scenario: Некорректный subject
- **WHEN** subject не начинается с точного имени ветки и двоеточия либо не содержит краткого сообщения
- **THEN** публикация не изменяет Git history и UI предлагает исправить сообщение

### Requirement: Атомарная публикация задачи
Система MUST повторно проверить task workspace, HEAD, разрешённые paths и fingerprint непосредственно перед commit, SHALL создать commit с подтверждённым пользовательским сообщением только из подтверждённого набора и SHALL выполнить обычный push текущей ветки после явного действия пользователя.

#### Scenario: Успешная публикация новой ветки
- **WHEN** fingerprint актуален, branch совпадает с задачей и remote принимает обычный push
- **THEN** система создаёт commit с подтверждённым сообщением, устанавливает upstream безопасным refspec и сообщает об успешной публикации задачи

#### Scenario: Diff изменился после preview
- **WHEN** разрешённые файлы изменились после генерации сообщения
- **THEN** система не создаёт commit, обновляет preview и формирует сообщение заново

#### Scenario: Remote опережает задачу
- **WHEN** обычный push отклонён как non-fast-forward
- **THEN** система сохраняет локальную версию, не выполняет force или merge и сообщает, что ветка задачи была обновлена в другом месте

## MODIFIED Requirements

### Requirement: Git status и diff
Система SHALL вычислять staged и unstaged status и diff активного Store worktree для публикации и вторичной технической диагностики, не делая Git index пользовательским workflow.

#### Scenario: Изменённый файл
- **WHEN** файл Store отличается от HEAD
- **THEN** основной workspace показывает компактный признак локальных изменений, а подробный Git status и diff доступны в технической диагностике

## REMOVED Requirements

### Requirement: Выборочный commit
**Reason**: Ручной stage заменён публикацией OpenSpec-артефактов задачи с точным preview; сообщение редактируется в предметном publication dialog и при желании генерируется agent.

**Migration**: Пользователь выбирает «Опубликовать» в контексте задачи; низкоуровневый API может сохраняться для совместимости, но не является основным UI.

### Requirement: Push с upstream
**Reason**: Выбор remote и upstream является технической деталью task publication и не должен требовать знания Git.

**Migration**: Публикация использует настроенный remote и безопасно устанавливает upstream одноимённой ветки задачи; ошибки показываются предметным языком.
