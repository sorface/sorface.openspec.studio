## ADDED Requirements

### Requirement: Лаконичный task-first интерфейс
Workspace SHALL показывать в основной верхней панели компактный однострочный selector текущей задачи с семантической branch-иконкой и одно основное действие «Опубликовать», SHALL использовать ясную визуальную иерархию и MUST NOT показывать лишнюю декоративную иконку, подпись категории, карточную рамку, HEAD, stage, commit, fetch, upstream или push controls в основном сценарии.

#### Scenario: Обычная работа
- **WHEN** task workspace загружен и не выполняется публикация
- **THEN** header показывает название проекта, branch-иконку перед номером задачи, chevron и при необходимости спокойный индикатор локальных изменений, а icon-only действие публикации находится в центральной группе рядом со статусами локального server и сохранения файла

#### Scenario: Есть локальные изменения
- **WHEN** разрешённые файлы текущей задачи отличаются от HEAD
- **THEN** selector или соседняя нейтральная подпись сообщает «Есть локальные изменения» без Git-терминов и яркого warning-состояния

#### Scenario: Техническая диагностика
- **WHEN** пользователю нужны подробности ошибки
- **THEN** вторичное меню открывает Git-диагностику, не добавляя её controls в постоянную навигацию

#### Scenario: Узкий viewport
- **WHEN** header не помещает проект, selector и основное действие в одну строку
- **THEN** selector остаётся видимым, а вторичные элементы сворачиваются без горизонтального overflow

### Requirement: Переключатель задачи
Task selector SHALL поддерживать поиск по ранее открытым task worktree и локальным веткам, SHALL предоставлять одно поле для открытия новой либо существующей задачи и MUST NOT объяснять пользователю внутреннюю Git-механику в popover.

#### Scenario: Выбор недавней задачи
- **WHEN** пользователь открывает selector и выбирает `BILL-1842`
- **THEN** компактный popover показывает поле и список задач, закрывается после подтверждения backend и показывает loading только в зависимых панелях

#### Scenario: Открытие по номеру
- **WHEN** пользователь вводит `BILL-1907`
- **THEN** selector показывает краткое описание будущего действия и позволяет подтвердить его одной основной кнопкой

#### Scenario: Ошибка переключения
- **WHEN** backend отклоняет имя или не может открыть worktree
- **THEN** popover остаётся открыт, сохраняет введённое значение и показывает исправимую ошибку рядом с полем

### Requirement: Компактное подтверждение публикации
Workspace SHALL немедленно показывать публикацию в небольшом dialog с номером задачи, количеством артефактов, редактируемым commit message, опциональным действием генерации и одним основным подтверждением.

#### Scenario: Preview готов
- **WHEN** backend подготовил актуальный diff preview
- **THEN** dialog открывается без ожидания agent, показывает задачу, краткий состав, редактируемые subject/body и действия «Отмена», «Сгенерировать» и «Опубликовать»

#### Scenario: Пользователь запросил генерацию
- **WHEN** пользователь выбирает «Сгенерировать»
- **THEN** progress показывается только у действия генерации, остальные данные dialog остаются видимыми, а успешный русский результат заменяет subject/body после явного ответа agent

#### Scenario: Ручная публикация
- **WHEN** пользователь задаёт допустимый subject вручную и не запускает agent
- **THEN** основное подтверждение остаётся доступным и использует введённое сообщение

#### Scenario: Публикация выполняется
- **WHEN** пользователь подтвердил публикацию
- **THEN** основное действие показывает спокойное progress-состояние, предотвращает повторный запуск и не блокирует чтение других задач

#### Scenario: Публикация завершена
- **WHEN** commit и push завершились успешно
- **THEN** dialog закрывается, локальный признак изменений обновляется и появляется краткое ненавязчивое уведомление с номером задачи

## MODIFIED Requirements

### Requirement: Контекст workspace
Система SHALL получать контекст workspace из локального API и показывать в верхней панели активный проект, текущую задачу/ветку и доступность основного действия без демонстрационных данных и без обязательного отображения Store path, HEAD или AI-модели.

#### Scenario: Контекст загружен
- **WHEN** локальный API возвращает активный проект и task workspace
- **THEN** UI показывает подтверждённые название проекта и номер задачи, а технические пути и инструменты оставляет во вторичных настройках

#### Scenario: Инструмент недоступен
- **WHEN** Git либо обязательный для выбранного действия CLI не обнаружен
- **THEN** UI сохраняет task context, блокирует только зависимое действие и показывает доступное исправление во вторичной информации
