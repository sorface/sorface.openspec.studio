## MODIFIED Requirements

### Requirement: Границы управления worktree
Система SHALL создавать и переиспользовать task worktree только внутри управляемого project-space либо внутри изолированного каталога данных приложения, MUST проверять принадлежность worktree исходному Store и MUST NOT автоматически удалять worktree с локальными изменениями.

#### Scenario: Создание task worktree
- **WHEN** пользователь открывает задачу, для ветки которой ещё нет worktree
- **THEN** backend создаёт уникальный управляемый каталог, проверяет общий Git repository identity и сохраняет связь с проектом и веткой

#### Scenario: Выбор недоступного worktree
- **WHEN** сохранённый каталог недоступен или больше не принадлежит Store
- **THEN** система не меняет активный worktree и сообщает причину без файловой мутации

#### Scenario: Изменённый worktree
- **WHEN** task worktree содержит staged, unstaged либо untracked файлы
- **THEN** система сохраняет каталог при переключении задачи и не выполняет stash, commit, discard или cleanup

### Requirement: Смена активного worktree
Система SHALL атомарно сохранять выбранный task workspace и обновлять файловое дерево, Git status, OpenSpec status и связанные черновики после выбора задачи без выполнения checkout в покидаемом worktree.

#### Scenario: Успешное переключение
- **WHEN** пользователь выбирает доступный task workspace того же Store
- **THEN** все новые запросы workspace начинают работать в контексте выбранного пути, а уже запущенные операции сохраняют прежний контекст

#### Scenario: Ошибка сохранения выбора
- **WHEN** active task workspace невозможно сохранить в локальной базе
- **THEN** система сохраняет прежний активный контекст и не показывает новый task selector как подтверждённый
