## ADDED Requirements

### Requirement: Прозрачное удаление активного change
Система SHALL позволять удалить активный OpenSpec change только после показа полного состава затрагиваемых файлов, предупреждения о необратимости и ввода точного идентификатора change.

#### Scenario: Предварительный просмотр удаления
- **WHEN** пользователь выбирает действие удаления активного change
- **THEN** UI показывает имя change, количество и относительные пути всех файлов, которые будут удалены, не изменяя Store

#### Scenario: Подтверждённое удаление
- **WHEN** пользователь ввёл точный идентификатор change и подтвердил удаление при неизменившемся fingerprint
- **THEN** система удаляет только каталог выбранного активного change и обновляет список changes и дерево документов

#### Scenario: Имя подтверждения не совпадает
- **WHEN** введённое значение не совпадает с точным идентификатором выбранного change
- **THEN** действие удаления остаётся недоступным и Store не изменяется

#### Scenario: Состояние change устарело
- **WHEN** состав или состояние change изменились после загрузки предварительного просмотра
- **THEN** система отклоняет удаление с `OPENSPEC_STATUS_STALE`, сохраняет Store и предлагает обновить данные

#### Scenario: Попытка удалить архивный change
- **WHEN** запрос указывает change внутри `openspec/changes/archive`
- **THEN** система отклоняет запрос как недопустимый и не удаляет файлы

#### Scenario: Небезопасный путь change
- **WHEN** идентификатор содержит traversal, абсолютный путь, option-like значение или разрешается через symlink за пределы активных changes
- **THEN** система отклоняет запрос до файловой операции и сохраняет данные Store

#### Scenario: Удаление без Agent CLI
- **WHEN** пользователь подтверждает удаление активного change
- **THEN** система выполняет контролируемую локальную операцию без запуска AI provider и не выполняет commit или push
