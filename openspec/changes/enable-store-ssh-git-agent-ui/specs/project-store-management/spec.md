## ADDED Requirements

### Requirement: Создание проекта из Git URL
Система SHALL позволять создать проект клонированием произвольного Git-репозитория по SSH или HTTPS Git URL в автоматически выбранный изолированный project-space внутри `~/.osstudio/projects` и SHALL сохранять проект после проверки Git worktree.

#### Scenario: Успешное SSH-клонирование Store
- **WHEN** пользователь вводит корректный SSH Git URL и название проекта
- **THEN** система неинтерактивно клонирует репозиторий, проверяет, что результат является отдельным Git worktree, затем создаёт и выбирает проект с локальным `storePath`

#### Scenario: Ошибка SSH-аутентификации
- **WHEN** системный ssh-agent не предоставляет подходящий ключ или remote отклоняет публичный ключ
- **THEN** система не создаёт проект и возвращает `GIT_AUTH_FAILED` с рекомендацией проверить ssh-agent без вывода ключей или credentials

#### Scenario: Репозиторий без OpenSpec-структуры
- **WHEN** clone завершён, но в репозитории отсутствуют `.openspec-store/store.yaml`, ожидаемые YAML-ключи или каталог `openspec/`
- **THEN** система создаёт проект без ошибки и показывает пустое OpenSpec-состояние до появления поддерживаемых документов

#### Scenario: Результат не является Git worktree
- **WHEN** операция не создала доступный отдельный Git worktree
- **THEN** система возвращает `INVALID_STORE`, не сохраняет проект и удаляет только каталог, созданный текущей незавершённой операцией

#### Scenario: Управляемый локальный каталог
- **WHEN** начинается клонирование Store или контекстного Git-репозитория
- **THEN** backend создаёт уникальный project-space с подкаталогами `store` и `repositories`, не смешивает данные разных проектов, а frontend не запрашивает и не отправляет локальный путь

### Requirement: Разделение локального пути и Git URL
Система MUST принимать в режиме локального Store только абсолютный путь существующего каталога и MUST отклонять Git URL как `storePath`.

Пользовательский мастер создания нового проекта MUST NOT запрашивать локальный путь и SHALL создавать только управляемые project-space из Git URL. Низкоуровневое локальное API MAY сохраняться для обратной совместимости.

#### Scenario: SSH URL в поле локального Store
- **WHEN** пользователь вводит `git@host:owner/repository.git` в поле локального пути
- **THEN** система не создаёт проект и предлагает переключиться в режим клонирования Store
