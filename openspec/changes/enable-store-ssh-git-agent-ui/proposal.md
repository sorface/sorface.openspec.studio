## Why

Текущий workspace показывает Git и выбор agent CLI, но элементы намеренно отключены, а создание проекта принимает SSH URL как локальный `Store path`, после чего дерево документов и AI-контекст завершаются ошибкой. Пользователю нужен сквозной рабочий сценарий: клонировать Store по SSH, открыть его как проект, видеть Git-состояние и выбрать доступный agent CLI.

## Цель

Сделать основные обещанные действия workspace работоспособными через локальный backend: создание проекта из Git URL, просмотр Git status/diff активного Store и сохранение настроек Codex/GigaCode для реального запуска AI-операций.

## Scope

- Добавить создание проекта из SSH/HTTPS Git URL в автоматически управляемом изолированном каталоге проекта под `~/.osstudio/projects`, безопасным неинтерактивным clone и проверкой Git worktree до сохранения проекта.
- Не позволять сохранять Git URL в поле локального `Store path`; показывать понятную валидацию и восстановление.
- Добавить backend API для Git status и diff активного Store.
- Сделать Git-панель доступной в workspace и загружать данные из backend с состояниями loading, empty и error.
- Добавить выбор обнаруженного agent CLI и необязательной модели, сохранять настройки проекта через backend и восстанавливать их после перезапуска.
- Согласовать header и AI-контроллер: один и тот же выбранный provider, без скрытого fallback, вводящего пользователя в заблуждение.
- Блокировать Git и AI действия только при недоступном или некорректном Git worktree с конкретным объяснением; OpenSpec-метаданные и документы в репозитории являются необязательными.
- Покрыть новые API, валидацию и frontend-сценарии автоматическими тестами.

## Вне scope

- Commit, push, force push и управление upstream.
- Создание или удаление Git worktree.
- Хранение SSH-ключей, токенов или иных secrets внутри приложения.
- Автоматическое исправление структуры клонированного Store.
- Подключение новых AI-провайдеров помимо уже поддерживаемых Codex и GigaCode.

## What Changes

- Мастер создания нового проекта принимает название и Git URL; локальный путь и project-space выбирает backend. Подключение произвольного локального пути не показывается в пользовательском UI.
- Все управляемые данные приложения размещаются внутри `~/.osstudio`; Store и контекстные репозитории каждого проекта находятся в отдельном project-space и не требуют знания локальных путей пользователем.
- Backend атомарно создаёт проект после успешного clone и проверки Git worktree, не требуя `.openspec-store/store.yaml`, конкретных YAML-ключей или каталога `openspec/`.
- Git-кнопка открывает панель реального статуса и diff активного Store вместо disabled-заглушки.
- Кнопка истории выбранного Markdown-файла открывает read-only Git-историю с коммитом, автором, датой и сообщением, включая loading, empty и безопасное error-состояние.
- Кнопка AI открывает настройки из доступных backend capabilities и сохраняет provider/model в проект.
- Название раздела в sidebar отображается как `OpenSpec`.
- Desktop workspace использует увеличенные читаемые размеры без корневого CSS `zoom`, чтобы координаты курсора визуального редактора оставались корректными, а его toolbar не был непропорционально крупным.
- Визуальный Markdown-редактор сохраняет согласованную вертикальную геометрию маркеров списков, checkbox, цитат и содержимого многострочных блочных элементов.
- Preview и Split отображают семантически отрендеренный Markdown через read-only Milkdown вместо сырого исходника в `<pre>`.
- Служебная нормализация Markdown при инициализации Milkdown не помечает документ изменённым; предупреждение при переключении файлов появляется только после реального пользовательского редактирования.
- Визуальный редактор сохраняет нативную историю undo/redo, а сочетание сохранения использует `Cmd+S` на macOS и `Ctrl+S` на Windows/Linux без конфликта с обработчиками Milkdown.
- Артефакты внутри каждого OpenSpec change отображаются в рабочем порядке `proposal.md` → `specs/` → `design.md` → `tasks.md`, а не в общем алфавитном порядке.
- Дерево визуально различает аналитические артефакты (`proposal.md`, `specs/`) и артефакты разработчика (`design.md`, `tasks.md`) текстовой role-меткой, цветом и доступным описанием.
- Дерево OpenSpec прокручивается независимо от sidebar, позволяет сворачивать каталоги, а selector agent CLI использует ведущую иконку `✦` и отдельный корректно выровненный индикатор раскрытия.
- Ошибочный проект с URL вместо пути получает диагностируемое состояние, а новые такие проекты отклоняются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `project-store-management`: добавляется наблюдаемый сквозной сценарий клонирования произвольного Git-репозитория по SSH/HTTPS URL и запрет URL в локальном пути.
- `git-delivery`: Git status и diff становятся доступны через локальный API и рабочую панель без включения commit/push.
- `ai-operations`: обнаруженный provider можно выбрать, сохранить в проекте и использовать без скрытого frontend fallback.
- `workspace-experience`: ранее отключённые Git и AI controls получают рабочие состояния и понятные ошибки некорректного Store.

## Impact

- Backend: project validation/clone, Git read API, HTTP routes и безопасное отображение ошибок.
- Frontend: project wizard, Git panel, provider settings, согласование состояния AI и Store.
- Storage schema не меняется: используются существующие `store_path`, `default_ai_provider` и `default_model`.
- Системные `git`, `ssh-agent`, Codex и GigaCode продолжают запускаться только backend-процессом с ограниченным окружением, timeout и безопасным выводом.

## Риски

- SSH clone не может показывать интерактивный prompt, поэтому ключ и `known_hosts` должны быть подготовлены в системном окружении до запуска приложения.
- Репозиторий без OpenSpec-структуры создаёт проект с пустым OpenSpec-состоянием; это не считается ошибкой clone.
- Большой diff требует ограничения размера ответа, чтобы не перегружать frontend и backend.
