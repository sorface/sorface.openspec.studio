## Why

Текущий интерфейс использует backend только для health-check, а проекты, документы и действия workspace имитируются статическими данными и локальным React state. Из-за этого UI не отражает сохранённые сервером данные, не восстанавливает проект после перезапуска и создаёт ложное впечатление работающих операций.

## Цель

Сделать существующий backend API источником истины для доступных системных данных и управления проектами, обеспечив пользователю реальные загрузку, выбор и изменение проектов с явными состояниями интерфейса.

## What Changes

- Добавить единый типизированный frontend API client для health, session/CSRF, capabilities и Projects CRUD.
- Загружать список проектов из backend, позволять создать, выбрать, переименовать и удалить локальную конфигурацию проекта.
- Отображать выбранный проект, Store path, AI provider/model и серверные capabilities вместо захардкоженных значений там, где backend уже предоставляет данные.
- Обрабатывать loading, empty, success, error и backend unavailable; не выдавать имитацию операции за успешный серверный результат.
- Передавать CSRF token во всех изменяющих запросах и показывать безопасные сообщения API с correlation ID для диагностики.
- Добавить frontend-тесты API-клиента и пользовательских состояний интеграции.

## Scope

- Существующие endpoints `/api/v1/system/health`, `/api/v1/system/session`, `/api/v1/system/capabilities` и `/api/v1/projects`.
- Верхняя панель и управление проектами в текущем workspace.
- Сохранение выбора активного проекта на стороне UI между перезагрузками с проверкой, что проект всё ещё существует.
- Отказоустойчивое read-only представление при недоступном backend.

## Вне scope

- Новые backend endpoints для файлов, Markdown-черновиков, Git, OpenSpec CLI и AI-операций.
- Реальная запись редактора в working tree и отправка prompt в AI.
- Проверка Store path и подключение/клонирование Store сверх поведения уже реализованного Projects API.
- Полноценный отдельный экран списка проектов или мастер первоначальной настройки.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `workspace-experience`: UI получает данные workspace через backend и показывает различимые состояния загрузки, пустого результата, ошибки и недоступности.
- `project-store-management`: доступные операции создания, открытия, переименования и удаления проекта выполняются через Projects API, а выбранный проект восстанавливается безопасно.
- `local-platform`: browser-клиент использует session/CSRF и единый формат ошибок локального API для изменяющих запросов.

## Impact

- Frontend: `features/system`, новый project API/model/hooks, `WorkspaceHeader` и `OpenSpecWorkspace`.
- Backend API: контракт не расширяется; используются существующие system и projects endpoints.
- Хранение: SQLite остаётся источником project metadata, а идентификатор активного проекта может храниться в browser storage только как UI preference.
- Тесты: добавляются проверки запросов, CSRF, ошибок и основных состояний project switcher.
- Зависимости: новые runtime-зависимости не требуются.

## Риски

- Сохранённый в browser идентификатор может указывать на удалённый проект; UI должен выбрать доступный fallback либо показать empty state.
- Session token может устареть после перезапуска backend; клиент должен обновить session и не повторять изменяющую операцию бесконечно.
- Недоступность backend не должна приводить к потере уже введённого несохранённого текста или маскироваться под успешную запись.
