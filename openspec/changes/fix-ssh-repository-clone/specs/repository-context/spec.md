## MODIFIED Requirements

### Requirement: Клонирование кодового репозитория
Система SHALL клонировать кодовый Git-репозиторий по HTTPS или SSH URL только в выбранный пользователем отсутствующий или пустой каталог после проверки допустимости URL и целевого пути.

#### Scenario: Успешное клонирование
- **WHEN** пользователь подтверждает корректный Git URL и доступный пустой каталог
- **THEN** система клонирует репозиторий, проверяет его связь со Store проекта и регистрирует подключение только после успешной проверки

#### Scenario: SSH clone с настроенным agent
- **WHEN** пользователь указывает SSH URL и ключ для host доступен в системном ssh-agent
- **THEN** Git-процесс использует agent socket приложения и клонирует репозиторий без запроса ключа или passphrase в UI

#### Scenario: SSH-аутентификация недоступна
- **WHEN** SSH host отклоняет доступ или agent не содержит подходящего ключа
- **THEN** операция завершается с `GIT_AUTH_FAILED`, не раскрывает stderr или credentials и предлагает проверить системный ssh-agent

#### Scenario: Host key не подтверждён
- **WHEN** SSH не может проверить host key
- **THEN** операция завершается с `SSH_HOST_KEY_FAILED` без автоматического изменения `known_hosts`

#### Scenario: Непустой целевой каталог
- **WHEN** выбранный целевой каталог содержит файлы до начала операции
- **THEN** система возвращает `CLONE_TARGET_NOT_EMPTY` и не изменяет содержимое каталога

#### Scenario: Недопустимая схема URL
- **WHEN** Git URL использует неподдерживаемую схему или интерпретируется как аргумент CLI
- **THEN** система возвращает `INVALID_GIT_URL` до запуска Git

### Requirement: Наблюдаемая clone-операция
Система SHALL выполнять clone как длительную операцию со статусами queued, running, validating, completed, cancelled и failed, безопасным прогрессом, terminal error и возможностью отмены.

#### Scenario: Прогресс клонирования
- **WHEN** clone находится в состоянии running или validating
- **THEN** UI показывает текущий статус и получает новые события без блокировки остальных проектов

#### Scenario: Ошибка клонирования
- **WHEN** clone переходит в failed
- **THEN** UI показывает безопасные `errorCode`, `errorMessage`, correlation ID и действие повторного открытия формы

#### Scenario: Отмена клонирования
- **WHEN** пользователь отменяет running clone
- **THEN** система завершает дерево Git-процесса, переводит операцию в cancelled и удаляет только каталог, созданный этой незавершённой операцией
