## ADDED Requirements

### Requirement: Подтягивание commits из другой ветки
Система SHALL позволять применить явно выбранные commits из доступной локальной или remote-tracking ветки к текущей ветке активного Store worktree.

#### Scenario: Список commits для подтягивания
- **WHEN** пользователь выбирает исходную ветку, отличную от текущей
- **THEN** система возвращает ограниченный список commits, которые есть в исходной ветке и отсутствуют в текущей ветке, от новых к старым с hash, датой, автором и сообщением

#### Scenario: Успешное применение commits
- **WHEN** пользователь выбирает один или несколько commits из списка и запускает подтягивание
- **THEN** система применяет commits к текущей ветке в порядке от старых к новым и возвращает завершённую Git operation

#### Scenario: Пустой выбор commits
- **WHEN** пользователь запускает подтягивание без выбранных commits
- **THEN** система отклоняет запрос с `GIT_EMPTY_SELECTION`, а HEAD и working tree не изменяются

#### Scenario: Недоступная исходная ветка
- **WHEN** выбранная исходная ветка отсутствует среди локальных и remote-tracking refs активного Store
- **THEN** система отклоняет запрос с `GIT_BRANCH_NOT_FOUND` до запуска изменяющей Git operation

#### Scenario: Dirty worktree
- **WHEN** активный Store содержит staged или unstaged изменения
- **THEN** система отклоняет подтягивание с `WORKTREE_DIRTY`, а HEAD, index и working tree не изменяются

#### Scenario: Конфликт cherry-pick
- **WHEN** применение выбранного commit приводит к конфликту
- **THEN** система останавливает operation со статусом `failed`, возвращает `GIT_CHERRY_PICK_CONFLICT` и оставляет репозиторий в состоянии Git conflict для ручного разрешения пользователем

### Requirement: Ограничение подтягивания commits
Система MUST выполнять подтягивание commits только для активного Store проекта и MUST NOT выполнять эту операцию для подключённых read-only кодовых репозиториев.

#### Scenario: Активный Store
- **WHEN** запрос подтягивания commits относится к Git API активного Store проекта
- **THEN** система валидирует Store path через существующие ограничения локального проекта и запускает операцию только в этом worktree

#### Scenario: Кодовый репозиторий
- **WHEN** пользователь работает с подключённым кодовым репозиторием контекста
- **THEN** UI не предоставляет действие подтягивания commits, а backend Git API не принимает path или repository id для обхода активного Store
