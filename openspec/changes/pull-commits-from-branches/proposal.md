## Why

Аналитику и разработчику нужно переносить уже готовые изменения из другой ветки в текущую задачу без ручного выхода в терминал. Сейчас Git-панель умеет commit/push/fetch/switch, но не даёт безопасно применить отдельные commits к активному task worktree.

## Цель

Добавить управляемый сценарий подтягивания commits из другой ветки в текущую задачу с предварительным выбором источника и явной обработкой конфликтов.

## Scope

- UI показывает действие импорта commits в активную задачу из Git-панели или контекста задачи.
- Пользователь выбирает исходную ветку и один или несколько commits, отсутствующих в текущей ветке.
- Backend выполняет безопасный `git cherry-pick` выбранных commits только в активном Store worktree.
- Длительная операция отображается через существующую модель Git operations с прогрессом, результатом и ошибками.
- При конфликте система останавливает операцию, сообщает понятное состояние и оставляет разрешение конфликта пользователю.

## Вне scope

- Автоматическое разрешение merge conflicts.
- Merge/rebase целых веток вместо выборочного применения commits.
- Изменения в подключённых read-only кодовых репозиториях.
- Force push, автоматический push после подтягивания commits или изменение remote configuration.

## What Changes

- Добавляется API для списка candidate commits из выбранной ветки относительно текущей.
- Добавляется API для запуска операции применения выбранных commits в активный task worktree.
- Git-панель получает компактный workflow: выбрать ветку, увидеть commits, применить выбранные.
- Ошибки dirty worktree, неизвестной ветки, пустого выбора и конфликтов получают стабильные коды и безопасные сообщения.

## Capabilities

### New Capabilities

- _Нет._

### Modified Capabilities

- `git-delivery`: добавляется безопасное подтягивание выбранных commits из другой ветки в текущую задачу активного Store.
- `workspace-experience`: добавляется пользовательский workflow выбора ветки и commits в Git/task UI.

## Impact

- Backend: доменная модель Git, `GitController`, `GitService`, async Git operations и integration tests.
- Frontend: Git API client, controller hook, Git panel components, типы операций и UI states.
- Specs: delta для `git-delivery` и `workspace-experience`.

## Риски

- `cherry-pick` может оставить repository в конфликтном состоянии; API должен явно обнаруживать это и не маскировать как общий сбой.
- Применение commits в dirty worktree повышает риск смешивания изменений, поэтому операция должна требовать чистый worktree до запуска.
- Список commits должен быть ограничен и отсортирован предсказуемо, чтобы UI не перегружался на длинных ветках.
